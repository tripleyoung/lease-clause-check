# 계약서 특약 점검기

전월세 계약서의 특약이나 헬스장·PT 이용약관을 붙여 넣으면, **정해진 점검 항목을 하나도 빼지 않고** 항목마다 `보호됨 · 언급 없음 · 위험`을 표시하고, 근거가 된 **원문 문장**과 **법령 조문**, 상대에게 **물어볼 질문**, **넣어 달라고 할 대안 문구**를 보여 줍니다.

> 법률 자문이 아닙니다. 계약 전 공인중개사·법률 전문가에게 확인하세요.

## 왜 만들었나

- 첫 자취를 준비하는 사회초년생은 특약 문구에서 돈을 잃을 수 있는 조항을 놓칩니다. 무엇을 봐야 하는지 모르기 때문입니다.
- ChatGPT에 그냥 붙여 넣으면 답이 매번 다르고, **무엇을 빠뜨렸는지 알 수 없고**, 근거가 없으며, 주민번호·전화번호가 그대로 외부로 나갑니다.
- 2026년 임대차 거래의 약 62%가 월세라서(1~7월 전국, 국토부 실거래 집계 보도) 전세만이 아니라 월세·반전세 특약도 다룹니다.

## 어떻게 다른가

| 그냥 ChatGPT | 이 도구 |
|---|---|
| 답이 매번 다르고 빠진 걸 모름 | 점검팩의 모든 항목을 반드시 판정(빠지면 '자동 판정 실패'로 표시) |
| "위험해 보여요" | 원문 문장 인용 + 법령 조문 인용. 원문에 없는 인용은 걷어 냄 |
| 개인정보가 그대로 나감 | AI 호출 **전에** 서버에서 가리고, 가린 내용을 먼저 보여 줌 |
| 숫자 기준을 어림 | 증액 5%, 위약금 10% 같은 기준은 규칙으로 계산 |
| 개선했는지 알 수 없음 | 같은 정답 표로 v0 → v1 → v2 를 잼 |

## 점검팩

엔진은 계약 종류를 모르고, 점검 기준은 '팩'으로 끼웁니다(`server/packs.ts`).

| 팩 | 항목 | 근거(국가법령정보센터 원문 발췌, `knowledge/`) |
|---|---|---|
| 전월세 임대차 특약 | 11개 (근저당 금지, 전입·확정일자, 정보 제시, 보증금 반환, 2년 기간, 갱신요구권, 증액 한도, 중도 해지, 수선, 원상복구, 집주인 변경) | 주택임대차보호법 [시행 2026. 1. 2.], 민법 [시행 2026. 3. 17.] |
| 헬스장·PT 이용 약관 | 7개 (환불 가능, 위약금 비율, 차감 기준 가격, 시작 전 해지, 사업자 사정, 광고 불일치, 사은품) | 소비자분쟁해결기준 [별표 2] 체육시설업 (공정위 고시 제2025-14호) |

팩이 없는 계약서는 '점검 기준이 없는 종류라 참고용'으로 보여 주고 평가에서 뺍니다.

## 구조

```
화면(src/, React+Vite) ──POST /api/check──▶ api/check.ts ─▶ server/http.ts
                                                           │
   입력 검사(validate) → 개인정보 가림(pii) → [v2] 규칙 검사(rules)
   → AI 판정(check + prompts, Vercel AI SDK) → 결과 보정(repair)
                                                           │
                          근거 원문: knowledge/*.md (절 단위 인용)
```

다온 사주 AI와 같은 구조입니다: Vercel 함수 입구(`api/*.ts`)는 한 줄로 `server/*.ts` 처리기에 넘기고, 개발 서버(`vite.config.ts`)도 같은 처리기를 씁니다.

## 실행

```bash
npm install
cp .env.example .env   # LLM_PROVIDER 와 GEMINI_API_KEY(또는 OPENAI_API_KEY) 입력
npm run dev            # http://localhost:5193
```

Gemini는 Google AI Studio 무료 등급 키로도 됩니다. 키가 없으면 화면은 뜨고, 점검 버튼을 누르면 "서버에 GEMINI_API_KEY가 설정되지 않았어요"라고 알려 줍니다.

## 테스트

```bash
npm test                 # 단위 테스트(node:test) — 점검팩·정답 표·가림·규칙·채점·판정 보정·API
npm run typecheck
npx playwright test      # 화면: 빈 입력, 계약서 아닌 글, 개인정보 가림, 키 없음
```

## 평가

- 정답 표: `data/cases_dev.jsonl`(10건, 조정용) / `data/cases_test.jsonl`(20건, 최종 숫자). 모두 직접 만든 문장이고 개인정보는 가짜 값입니다.
- **정답 표는 규칙·프롬프트보다 먼저 커밋했습니다: `c5ee656`.** `git log --oneline` 에서 정답 표 커밋이 `server/rules.ts`·`server/prompts.ts` 커밋보다 앞섭니다.
- 채점 단위는 항목(케이스 × 팩의 점검 항목)입니다. 주 지표는 `위험` 재현율(놓친 위험)과 정밀도(헛경고).

```bash
npm run eval -- --version all --split dev    # 조정할 때
npm run eval -- --version all --split test   # 발표 숫자(한 번)
```

결과는 `results/summary_<split>.md` 와 케이스별 원본 `results/<split>_<version>.json` 에 남습니다. 측정 결과와 분석: [docs/evaluation.md](docs/evaluation.md).

| 버전 | 무엇이 다른가 |
|---|---|
| v0 | "불리한 조항을 찾아 줘" + 항목 이름만 (그냥 ChatGPT에 붙여 넣는 상황) |
| v1 | 항목 설명 + 원문 문장을 그대로 인용하게 강제 + 부정문 주의 |
| v2 | v1 + 항목별 근거 조문을 서버가 묶어 넣음 + 규칙 검사 결과 + 출력 보정 |

## 막는 장면

| 상황 | 동작 |
|---|---|
| 빈 입력·20자 미만 | AI를 부르지 않고 안내 |
| 4,000자 초과 | 특약·환불 부분만 잘라 넣으라고 안내 |
| 계약서·약관이 아닌 글 | 판정하지 않고 안내 |
| 주민번호·전화·계좌·동호수 | 서버에서 가린 뒤 미리 보기로 보여 주고 그 글만 AI로 보냄 |
| 키 없음·키 틀림·사용량 초과·시간 초과 | 원인 한 문장, 입력은 그대로 |
| AI가 항목을 빼먹음·형식이 틀림 | 화면이 멈추지 않고 그 항목을 '자동 판정 실패, 직접 확인'으로 표시 |
| AI가 원문에 없는 문장을 인용(v2) | 그 판정을 걷어 내고 직접 확인으로 표시 |

## 한계

- 정답 표는 설계자가 판단했고 법률 전문가의 검수를 받지 않았습니다.
- 근거는 레포에 고정한 발췌입니다(평가 재현을 위해). 법이 바뀌면 다시 확인해야 합니다. 다음 단계로 국가법령정보 Open API 기반 법령 조회 서버(MCP)를 붙여 현행 조문과 대조할 계획입니다.
- 특약·약관 텍스트만 받습니다. 사진·PDF·등기부등본은 다루지 않습니다.
- 소비자분쟁해결기준은 분쟁 해결의 기준이며 계약을 바로 무효로 만드는 규정은 아닙니다.

## 출처

- 국가법령정보센터 — 주택임대차보호법, 민법, 소비자분쟁해결기준(행정규칙, [별표 2])
- 법령 본문은 저작권법 제7조에 따라 보호 대상이 아닙니다.
